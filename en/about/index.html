DBG Desk

Open a file, step through instructions and find where a value changes. Use it directly in your browser or connect to GDB on your computer. DBG Desk is not an official OllyDbg or GDB service.

Run in your browser

Run x86/x64 instructions from ELF and PE files. Click an address to set a breakpoint, then inspect or edit registers and memory. The examples include both 32-bit and 64-bit files. Save your latest session in this browser and reopen it later.

Only a few Linux calls, including read, write and exit, are handled. Programs that need Linux dynamic loaders, shared libraries or Windows DLLs and APIs may stop.

Connect to GDB on your computer

Use local GDB mode to attach to a process or inspect source lines, stack frames and local variables. Install Python and GDB, then start the local server. Conditional breakpoints, data breakpoints and thread selection are available here.

Linux uses the web input panel; Windows uses a separate console. What you can inspect depends on the program, operating system and debug symbols.

History and comparison

Local GDB mode keeps recent stopped states and shows changes in registers and memory. Save records as Markdown, or save paths, arguments and basic breakpoints as workspace JSON. You can also search memory for text or HEX patterns and read bytes as integers or floating-point values.

Stop history lets you inspect earlier values. It does not rewind the running program.

Guides

The guides cover GDB setup, breakpoints, memory errors and Python and JavaScript errors. References appear below each article. If something is wrong, send the article URL and your correction through the contact page.

Files and contact

Your files and debugging data are not uploaded. Browser mode runs on this device; local GDB runs against a process on your computer. Download the source as a ZIP. Contact uses public GitHub issues. No ads are currently shown.

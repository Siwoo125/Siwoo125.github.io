Notes
DBG Desk connects to GDB on your computer to inspect a real running program. Open an executable or attach by PID, then inspect instructions, registers, memory, and the call stack at a breakpoint. A Python local server and a compatible GDB are required. Files and debugging state are not uploaded to an external server.
Start with a small example and stop at main. F7 executes one instruction, F8 steps over a call, and F9 continues to the next breakpoint. Compare a function’s inputs and results to narrow down where a value becomes incorrect. The memory panel shows a stopped snapshot; it does not automatically establish object validity or diagnose the cause.
The debugger supports stopped-process memory and register edits and starting at the first instruction. Linux uses the web input panel; Windows uses a separate target console. File patching and reverse execution are not supported. Use the debugger for the relevant language for Python tracebacks and JavaScript exceptions. See the guides for investigation steps.
